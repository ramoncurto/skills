# Writing Great Skills

## When to use
You're creating or revising a skill in this kit. Use it to keep new skills consistent, discoverable, and actually useful to the agent that reads them.

## Steps
1. **One skill, one discipline.** If it needs "and," it's probably two skills. Scope tightly.
2. **Write a trigger-rich description.** One line stating what it does AND when to use it, packed with the words a user/agent would actually say. The agent auto-invokes off this line, so name the situations and symptoms, not just the capability.
3. **Match the folder structure.** Folder name = `name:` field = kebab-case. SKILL.md with the standard frontmatter (`name`, `description`) then body.
4. **Use the standard body sections.** `## When to use` (the triggering situations), `## Steps` (the discipline, ordered, concrete), `## Done when` (the completion bar).
5. **Concrete beats abstract.** Prefer real commands, snippets, and example phrasings over principles. Show the move, don't just name it.
6. **State a checkable Done when.** The reader should be able to tell unambiguously whether they're finished.
7. **Cut fluff.** No motivational preamble, no restating the obvious. Keep the whole file under ~70 lines so it's read, not skimmed past.
8. **Dogfood it.** Read your skill as if you were the agent mid-task: would the description fire at the right moment, and would the steps be enough to act?

## Done when
The skill is single-purpose, its description is trigger-rich and accurate, the body has When-to-use / Steps / Done-when with concrete guidance, it's under ~70 lines, and folder name matches the `name` field.
